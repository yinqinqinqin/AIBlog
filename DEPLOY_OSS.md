# OSS Deployment

This project can deploy the built Vite site to Alibaba Cloud OSS.

## First-time setup on a new machine

Install dependencies:

```bash
npm install
```

Create a local env file from the example:

```bash
cp .env.oss.example .env.oss
```

Edit `.env.oss` and fill in:

```bash
ALI_OSS_ACCESS_KEY_ID=your_access_key_id
ALI_OSS_ACCESS_KEY_SECRET=your_access_key_secret
```

Do not commit `.env.oss`.

## Deploy

Load the env file and deploy:

```bash
set -a
source .env.oss
set +a
npm run deploy:oss
```

Before every build, the project automatically regenerates article metadata from `articles/`.
The Markdown body is not bundled into the site JavaScript. During deploy, `dist/` is uploaded as the site and `articles/` is uploaded as remote content under `blog-content/articles/`.

## Update existing article body only

If you only edit the body of an existing Markdown file and do not change its title, date, excerpt, tags, category, cover, slug, or pinned fields, you do not need to rebuild the frontend.

Load the env file and sync only the article files:

```bash
set -a
source .env.oss
set +a
npm run sync:articles
```

The frontend article page reads Markdown from OSS at runtime, so refreshing the page will load the updated content after OSS/CDN propagation.

Run the full deploy instead when you add a new article, rename a Markdown file, move categories, or change frontmatter used by article cards and lists:

```bash
npm run deploy:oss
```

The default target is:

```text
Bucket: yin-qin
Endpoint: oss-cn-shanghai.aliyuncs.com
CDN: https://oss.an-hao.top/
```

## Notes

- Edit Markdown articles in `articles/`, not `src/data/generated/articles.ts`.
- `src/data/generated/articles.ts` is generated by `npm run generate:articles`; it stores metadata and each article's OSS `markdownUrl`.
- The deploy script uploads `dist/` plus Markdown content from `articles/`, and does not clear the bucket.
- The article sync script uploads only `articles/` and refreshes `https://oss.an-hao.top/blog-content/articles/`.
- The default article content URL prefix is `https://oss.an-hao.top/blog-content/articles/`.
- This bucket is also used as an image host, so global deletion is intentionally not part of this deploy flow.
- `index.html` is uploaded with no-cache headers.
- hashed assets under `assets/` are uploaded with long cache headers.
- source maps are skipped by default. Set `ALI_OSS_UPLOAD_SOURCEMAP=true` if you need to upload them.
- Set `ALI_CDN_REFRESH=false` if you do not want to refresh CDN after upload.

## Deploy under a subdirectory

To deploy to a prefix such as `/blog/`, set:

```bash
ALI_OSS_PREFIX=blog
```

Then run the same deploy command.
